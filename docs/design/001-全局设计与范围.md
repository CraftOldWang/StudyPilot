## 1. 定位

StudyAgent 是一个基于用户资料完成讲解、测验和复习卡片生成的学习 Agent。首个里程碑只证明两条纵向链路真实可运行：

1. 真实 PDF 进入知识库后可被 Agent 有出处地检索。
2. 用户从学习目标进入单知识点讲解、答疑、五题测验、三张卡片并完成。

AgentScope Java 2.0.1 是唯一 Agent Runtime。项目价值在于学习业务状态、受控知识检索、上下文治理和可查询轨迹，不自建平行 Runtime，也不靠演示用假数据伪造完整链路。

## 2. 首个里程碑

### M0 · 干净切换与真实 hello

- 把已提交的 Phase 2 成果纳入主线；Phase 3 未完成内容保留在 WIP 分支，按新设计选择性迁移或重写。
- 迁移仍有价值的旧实现后，清理旧 `modules/`、顶层 `infrastructure/` 和兼容层。
- 删除全部 Spring AI 代码和依赖，AgentScope 独立承担 Agent Loop、工具调用和 AgentState。
- 修复 S3 endpoint 启动问题，以真实 DeepSeek 完成 `/api/agent/hello`。
- 首版只有 `username='default-user'` 的初始用户；不建设注册、登录或 RBAC。

### M1 · 真实 PDF 到 RAG 工具

- 建立最小知识库实体，提供创建、列表、重命名和文档列表；不提供知识库删除及 S3/ES 级联清理。
- PDF 上传到对象存储，经 Tika 解析、结构化分块、DashScope embedding 后写入 Elasticsearch。
- 检索支持 BM25、向量、RRF 融合和父块回填。
- RAG 通过 `rag/retrieval` 应用服务与自定义 AgentScope `AgentTool`/`Toolkit` `knowledge_search` 暴露；不依赖 AgentScope 2.0.1 已整体弃用的 rag/`Knowledge` API。
- 模型只提交 query。M1 尚无学习会话时由 HTTP 入口验证 `userId + knowledgeBaseId` 并绑定运行上下文；M2 创建学习会话后从 `learningSessionId` 恢复同一 scope。
- 结果至少包含 `chunkId`、`content`、`provenance`、`score`。没有结果时必须明确没有资料依据，禁止编造来源。
- 全新 React 18 + TypeScript + Vite 前端提供知识库创建、PDF 上传、文档状态和检索演示。

### M2 · 单知识点学习闭环

- 学习会话绑定一个用户、一个学习目标、一个知识库和一个 AgentScope session；同时只有一个活跃知识点。
- 状态固定为 `NEW → EXPLAINING → QUIZZING → CARD_GENERATING → COMPLETED`。失败停留在当前状态，QUIZZING 中的用户追问不退回 EXPLAINING。
- Agent 通过工具请求推进状态；服务端注入身份和当前知识点，并只允许相邻转换。
- 通过 `learningSessionId` 恢复。MySQL 保存计划、知识点、测验、卡片等业务事实；AgentState 只保存最新短期对话状态，不做 checkpoint 历史或 fork。
- 测验固定五题，以一份 JSON 聚合持久化；提交后评分并解释错题，首版不设置及格门槛。
- 每个知识点生成三张复习卡片并持久化；首版不连接 AnkiConnect。
- 知识点完成 turn 结束时必须执行技术设计 §8.2 的 one-off 强制压缩契约；只有处理 `Optional`、写回同一 AgentState 并保存后才算完成。
- 首版由主 Agent 直接完成讲解、测验和卡片生成，不启用学习 subagent。
- 后端生成 traceId，并提供按 traceId 查询标准化时间线的 JSON API；首版不做 trace UI。
- 全新前端提供目标输入、学习计划、讲解/答疑、测验、卡片和状态展示；使用同步 REST，不做 SSE。

## 3. 模块边界

| 模块 | 首个里程碑职责 | 不拥有 |
|---|---|---|
| `identity` | 初始用户与服务端身份绑定 | 注册、登录、RBAC、多租户 |
| `ingest` | 上传、对象存储、PDF 解析、分块、embedding、索引写入与处理状态 | 检索策略 |
| `rag` | 混合检索、融合、父块回填、出处装配、`knowledge_search` 应用服务 | 文档摄入、AgentScope 已弃用 rag API、离线评测 |
| `agent` | AgentScope 集成、受控工具、AgentState、compaction 与 trace 映射 | 学习业务事实、平行 Runtime |
| `learning` | 学习计划、单知识点状态机、测验与卡片流程 | Agent Loop、检索实现 |
| `review` | 首版只保存复习卡片 | AnkiConnect 与复习调度 |
| 前端 | 知识库与学习闭环页面 | trace UI、运营配置 |

依赖方向：`learning → agent → rag`，`ingest → rag`，`learning → review`。`agent` 不依赖 `learning`；身份和权限 scope 一律由服务端注入。

包结构以根 [AGENTS.md](../../AGENTS.md) 为准。数据库实体和 Mapper 全局共享，Controller/Request/Response 属于各自子域的 `web/`。

## 4. 明确后续

以下能力不进入首个可运行里程碑：

- AnkiConnect 与复习调度。
- 用户画像、长期记忆和轻量知识图谱。
- RAG 黄金集、Recall@K、LLM-as-judge、轨迹评测和回归门槛。
- 高级 checkpoint/replay、状态 fork、确定性重放和 trace UI。
- 学习 subagent；后续引入时必须使用工具白名单和独立 ReAct loop。
- 音视频 ASR、多知识库会话、知识库删除与级联清理。
- SSE、通用 Agent 平台、Skill 市场、图形化流程编排、多角色协商。

## 5. 交付与判断标准

- 所有演示均使用真实 DeepSeek、真实 PDF、真实对象存储和真实 Elasticsearch，不硬编码答案。
- 外部依赖失败必须明确暴露；长流程失败能看出停在哪一步。
- 无检索结果时不产生伪造出处。
- 模块完成必须有实现者统一测试与独立 verifier review；实现文档在模块完成后编写。
- 实时状态只在根 [PROGRESS.md](../../PROGRESS.md) 更新；历史执行方案已归档，不再承担看板职责。
