## 有解释价值的差异

1. **RRF补回评分题、丢失书单题，总命中数持平。** 第2题VECTOR第1条就有教材和参考书单；BM25未检出，融合后正确子块未进入前5。原第1题则相反，由关键词路线补回评分规则。
2. **第13题父块预算丢证据。** VECTOR和RRF第3条直接写明寻找足够大的空闲分区、分割并标记；父块回填先保留换页主题的大块，最后没有留下分区分配职责的直接依据。
3. **同为命中不表示完整性相同。** 第25题VECTOR有代码、数据、堆等段的图示文字；RRF第3条额外带回完整段列表，包括子模块、公用库、初始化数据、符号表。按允许部分依据的口径两者都算命中，但RRF的证据更完整。
4. **父块不是必然增加有用信息。** 第19题父块保留覆盖/分区对换，却缺少虚拟存储原理；第27题父块保留LRU栈例图和访问顺序，但丢失前一子块的栈/链表完整操作步骤。两题仍有部分实质依据，因此粗粒度指标没有扣分。
5. **EAS是多块覆盖的例子。** VECTOR包含目标、能耗比较规则和迁移案例；RRF有目标和迁移案例，但缺少明确的能耗比较规则；4096预算的PARENT只保留案例等内容。此前将RRF也描述为缺少目标不准确，8192复核时已修正。按当前口径仍计命中，不应解读成回答质量相同。

这批结果显示纯向量已覆盖大部分问题的部分实质依据；RRF总体粗粒度命中数没有增加。父块组存在明显的预算装配问题，不能据此判断合理配置的父块回填是否有收益，也不能据此认定它应被移除。尚未修改业务默认检索策略。

## 父块预算复核（2026-09-11）

使用保存的28题子块排名、返回正文及查阅页中补读的现有索引父块正文，按业务使用的jtokkit 1.1.0 / CL100K_BASE重新计数，在本地重放整块装配过程。没有重新检索、向量化或生成回答。4096预算下，28题重放的父块ID顺序及总token数均与保存响应一致。

- 24/28题最终只有1个父块，4/28题有2个父块。
- 每题前5子块中，只有1～2个所属父块被保留：14题覆盖1个原始子块，14题覆盖2个。这是原始命中块的保留数量，不是答案召回率；新增父块区域也可能包含答案。
- 典型父块约2300～2400 token，两个通常已超过4096。实现按顺序保留整块，超额则跳过，且不保留被跳过父块对应的原始子块。因此“Top5子块”实际常退化成“首个父块”。

具体情况：

| 题目 | 已召回子块中的依据 | 父块组发生的变化 |
|---|---|---|
| 1 课程评分 | RRF第3子块含作业50%、期末50% | 先放2375 token的调度主题父块；评分父块2332 token被跳过 |
| 13 内存分配职责 | RRF第3子块含寻找足够大的空闲分区、分割与标记 | 先放2399 token的换页/分段主题父块；正确父块2354 token被跳过 |
| 27 LRU实现 | RRF第2子块含栈、链表的维护与淘汰步骤 | 先放2396 token父块，保留例图但跳过2379 token的步骤所在父块；粗粒度指标仍算命中 |
| 15 伙伴系统 | RRF前2子块已共同包含分配、二分拆分、释放合并条件 | 两子块属于同一父块；扩展增加碎片整理、对换、覆盖等其他主题，未见所指定5～8页的关键步骤因此补齐 |

这说明两种原因确实同时存在：部分问题的证据被预算装配丢弃；另一些问题用多个子块已足够，父块增加的内容并不回答当前问题。不能将所有题归结为问题太简单。

本地将预算改成8192后，第1、13、27题上述证据所在父块均可保留；12000可保留全部28题前5子块对应的所有父块。这仅是预算敏感性诊断，不是新的答案质量评测，也不证明扩大预算后的父块优于子块。后续若比较效果，应对两组采用相同预算，并按必要答案要点判断完整性；或者先保留命中子块，再利用剩余预算扩展邻近内容。

## 简历建议

- 基于Elasticsearch封装课程资料RAG检索工具，为讲解与测验提供可追溯依据；构建28道人工课程问题的检索评测集，对比关键词、向量、RRF融合及父块回填策略，分析检索命中与上下文完整性的取舍。
- 在阈值压缩之外，按知识点完成边界进行局部摘要压缩，保留关键结论与学习状态；固定5知识点、31轮学习流程中，相比不压缩，累计输入token减少约62%（含摘要调用）；持久化摘要与会话状态，支持中断恢复。

压缩实测为`1 - 390101 / 1041780 = 62.55%`，首轮为61.23%，不是62.3%。这是累计输入，不是单次上下文压缩率或费用降幅；两组学习模型调用为53/46次，属于相同用户脚本的Agent工作流对照，不能把所有差异归为固定调用列表的纯摘要效果。未测试“相比仅阈值压缩”的降幅。完整口径见[当前压缩实验](current-learning-compaction.md)。
