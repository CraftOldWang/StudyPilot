# 当前学习流程：知识点摘要与不压缩对照

2026-09-10，真实DeepSeek与后端API调用。当前流程的固定5知识点试跑中，知识点摘要方案累计输入token减少62.55%，累计输入＋输出减少61.63%，已包含5次摘要调用。计入同一份大纲的生成成本后，两方案总量对比减少58.58%。这是单组开发实验，不是稳定均值或无损压缩结论。

## 使用的流程

1. 使用完整OS知识库`2098021244222922753`中3.1进程课件，通过当前`/api/learning/plans`与`execute`生成多层大纲；没有手写大纲，也没有强行指定整份资料只有5点。规划任务`2098028620875309058`。
2. 将同一份生成结果创建为独立学习会话，重建知识点ID，不复制历史、题目、卡片或摘要。选择前5个连续叶子：进程概念的引入、计算资源共享与分时复用、并发与并行、并发效率意义、程序执行状态的保存与恢复。
3. 两组各31个真实用户回合：每点讲解、追问、2道四选一、交卷、错题答疑、2张卡片；第2点额外重写第二张卡，第5点要求回顾最初误区。均通过实际卡片确认与Anki导出后推进，共完成5点、10题、10张卡。两组统一选第1题A、第2题B，不向模型注入标准答案；这只是交互脚本，不代表真人的学习效果。
4. NONE完全保留上下文，不调用阈值摘要或知识点摘要。LOCAL在写卡前启动当前点摘要，重写期间保留原上下文，确认后用摘要替换当前点记录、丢弃卡片阶段对话。日常阈值临时提高为1000000以排除阈值压缩干扰；本次只有5次知识点摘要，没有阈值摘要。实验后恢复日常8000阈值。

模型为`deepseek-v4-flash`，摘要输出上限700，普通回复上限3000，工具步骤上限5；每段讲解要求约400字、追问与反馈约200字。没有为两组修改这些设置。课件检索使用当前服务及来源读取工具，未为压缩组换检索策略。

大纲实际生成一次，10次模型调用（包含3次字段校验失败对应的调用），输入29,727、输出25,253、合计54,980 token。为了比较“生成大纲＋学习”两种方案，可给各方案归入相同的这笔一次性成本：NONE为1,112,561，LOCAL为460,814，总量降幅58.58%。这不表示大纲实际生成了两次，也不是成功一次规划的稳定成本。

## 质量与首轮结果

- 首轮LOCAL会话`2098030073950048331`：输入403,898、总量419,970，分别减少61.23%/60.29%；5点流程完成，但第5点回顾时错误地说摘要未记录最初误区。
- 读取持久化上下文后发现第一点的误区及纠正仍然存在；没有被后续点替换掉。首轮最终上下文为5条摘要，NONE为134条消息。
- 为归档摘要补上明确的知识点序号与名称后，仅创建新LOCAL会话重跑，复用逻辑未变化的NONE结果与原大纲。最新回顾找回了“并发必须多核、多个任务真的同时执行”的原误区，并解释单核交替即可实现。这是修复后一次观察，不能据此认定标签必然解决所有回顾问题。
- 三个会话均只改写了第二张卡，第一张正反面保持原样；最终确认真实导出Anki。
- **仍有质量限制：** 新回顾把另一项测验错误与用户主动陈述并列为“明确说过”；首轮摘要还把助手的后续建议记为待处理事项，并出现“并发=单核”的过度简化。核心误区能回忆不等于所有信息都被准确保留。后续摘要质量改进应区分用户陈述、错题表现与助手建议，不能宣称无损压缩。

本次没有进行多次重复、跨课程泛化或独立人工质量评分。若简历写百分比，应限定为“固定5知识点学习流程对照”，暂不使用“保持回答质量不变”等表述。
