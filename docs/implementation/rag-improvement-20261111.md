# RAG 改进：观察与实测

## 运行范围

保留 StudyPilot 业务链路，KnowEngine 仅作为本地 MinerU/BGE 参考。完整教材、解析正文和权重保存在本机，仓库只记录参数、实现和结果。当前结果按下述阶段分别说明。

## 解析与切块

MinerU 2.5.4 CPU pipeline 经实际上传接口解析两页教材 PDF 和五页 OS PPTX。PPTX 由 LibreOffice 转 PDF，保存 Markdown、页码、章节、bbox 和图片。来源 API 已返回对应位置。两份样本分别形成 3 父/3 子块、5 父/5 子块。

两页教材的15个结构块，CL100K_BASE token 长度 P50/P90/最大为88/115/134；连续标题区间最大674 token。固定800/0在第二页正文中间截断句子；标题切分在 `Multilevel Indices` 处换块，保留该段。该样本的结构父块均小于800，因此 overlap=0/80/160 的块数相同，应换较长样本再比较重叠。

六份既有 OS 文本快照没有 Markdown 标题，空行段中位数只有7 token，图标签散落成多行。父块2400/0、结构子块800时：

| 子块 overlap | 子块数 | 累计待嵌入文本 token（本地估算） |
|---|---:|---:|
| 0 | 71 | 50,259 |
| 80 | 85 | 55,134 |
| 160 | 86 | 60,172 |

这些是离线切块统计，尚未对新切块调用 embedding。MinerU 仍有公式字符识别错误，需对照原页；清洗只做排版整理，不自动猜改公式。八页 CSAPP 曾在当前8GB Docker环境的公式识别阶段发生 OOM；将页推理批次和公式批次各降为1后，同样八页返回200，耗时137.7秒；随后十页数据库章节也返回200，耗时142.2秒。

较长真实样本在父2400/0、子800/0时，CSAPP的固定/递归/标题方式分别得到3/9、3/10、7/12个父/子块；数据库章节分别为3/8、3/8、11/14。递归模式保留CSAPP七张HTML表，降到400 token则四张表超限，需要窗口拆分；标题模式把图9.18链接与图注分到两块，递归保留两者。原文`m=12`被识别成`M=1 2`属于解析错误，换切块策略无法修复。

## 本地 BGE 重排：四题真实 API 对照

2026-11-11，使用既有完整 OS 课件知识库 `2098021244222922753`。直接提交用户原题，无查询改写；BM25候选20、最终Top5。对比 BM25 与 BM25+BGE，两次都调用实际 `/api/knowledge-bases/{id}/search`。这是小样本定位，后续正式评测仍需向量/RRF和新增资料。

权重：`onnx-community/bge-reranker-v2-m3-ONNX`，revision `6f5ff65298512715a1e669753bc754d2bc8f367b`，本地量化ONNX；CPU、每对输入上限1024 token。四题候选均无截断。表中“证据”是实际阅读返回片段后确认的答案内容。

| 用户题目 | 答案证据排名：BM25→BGE | 观察 | BM25 / BGE耗时 |
|---|---|---|---|
| 多级反馈队列是什么、有何特征 | 1→1 | 同一片段已有队列迁移、时间片、CPU/I/O密集型差异 | 256 / 27,027 ms |
| 基于EAS的调度是什么 | 3→2 | 能耗与性能目标片段提前；第一名仍是提出EAS问题的扩展阅读页，重排未解决“提到问题但未解答”的干扰 | 196 / 28,330 ms |
| 缺页异常处理流程 | 1→1 | 同一片段包含页表检查、异常、换入、更新和重执行步骤，图中文字顺序仍较乱 | 147 / 26,579 ms |
| LRU可能出现Belady现象吗 | 1→1 | 同一片段明确说明不会，并解释页面集合包含关系 | 161 / 23,786 ms |

本机四题平均耗时：BM25约190ms，加入BGE约26.4秒（另一次首次模型加载请求约31.2秒）。其他本地进程会影响耗时，当前CPU部署的重排代价明显，暂保持可选。没有因这四题宣称Hit@5提升。

本地原始请求/完整响应：`output/rag-reference/bge-os-cases/`；题目来自 `eval/rag/os-human-draft.jsonl`。

真实eval API使用BM25、Top3及4096 token预算，未调用embedding或重排。每题的三视图共享一次排名，父块/相邻扩展完整保留原先3条命中，并只补活动文档版本；以下为实际正文token：

| 问题 | 子块 | 父块扩展 | 相邻扩展 | 阅读结果 |

这些扩展提升了部分说明的丰富程度，尚未形成总体答案覆盖提升结论。完整响应在本地`output/rag-reference/context-cases/`。
