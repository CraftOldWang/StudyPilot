## 有解释价值的案例

1. **评分规则被关键词路线补回。** 课件1给出大作业50%、期末考试50%。BM25第1条包含规则，VECTOR前5条没有；RRF第3条保留规则。这是本次相对向量的新增命中。
2. **Clock排序改善。** VECTOR第1条为改进Clock，第2条才是基本Clock的访问位、环形链表和扫描规则。RRF把基本算法放到第1条；Hit@5不变，但答案位置更靠前。ENIAC、TLB、LRU/Belady等题三路本来就首条命中，无法在这些题上增加Hit。
3. **父块把已召回的评分依据挤掉。** RRF第1条误命中调度指标，其父块占2375 token；余下预算不足以容纳包含评分规则的完整父块，因此最后只留下错误主题的父块。正确子块本来可以放入预算。当前实现是整父块替换并按顺序跳过超预算块，缺少保留有效子块的处理；下一步若改回填，应优先解决这个已观察到的情况。
4. **多页不自动意味着父块获益。** 伙伴系统的定义/分配与释放/合并分布于相邻子块，VECTOR和RRF已同时检出；内存分配四算法也已由多个子块覆盖。父块增加文本，但本次没有带来新增命中。BM25在伙伴系统上仅有部分实现依据，命中率不能体现这种完整性差异。

本次只有10题，新增1题就是10个百分点，仅为开发试跑结果，不能填成稳定的全课程提升。保留原题继续补齐其他章节即可，不应为了制造差距故意绕开术语。参数/overlap对照还没有开展；这10题后续作为开发题，不再作为独立最终测试题。
